# Page Storage Guide

Understanding where and how pages are stored in [{$applicationname}].

## Overview

Every page is a file named by its UUID. Where the file lives depends on whether the page is public or private:

- __The pages folder__ (`data/pages/`) - every public page, whatever its [system-category]
- __A vault__ (`data/pages/vaults/<user>/<vault>/`) - a private page, readable only by its owner

The `required-pages/` folder in the release is not where pages are stored. It holds the original of each page that ships with [{$applicationname}]; each is copied into the pages folder once, the first time a release brings it.

## What the System Category Decides

Each [system-category] says where its pages may be stored (its __Stored__ value):

%%table-striped
|| Stored || Meaning || Categories ||
| `public` | Stored in the pages folder; never private | `system`, `documentation`, `addon` |
| `vault` | Stored in the pages folder, or privately in the owner's vault for that category | `general` |
| `none` | Never stored on the platform; saving one is refused | `developer` |
/%

```yaml
---
title: My Page
system-category: documentation  # What kind of page this is
uuid: abc123-...
---
```

### Shipped Pages

The pages that come with [{$applicationname}] (the `system` and `documentation` pages in `required-pages/`) and the pages an add-on brings are shipped pages, copies of their originals:

- They are copied in once; a page deleted on this site stays deleted
- Only administrators can edit, rename or delete them, and they can never be private
- An edit marks the copy as edited, and administrators are told
- An administrator can bring a copy back in line with the release from Admin › Required Pages Sync; an edited copy is left alone unless they choose to overwrite it

Whether a page is a shipped copy is decided for each page, so a `system` page made on this site is not treated as one.

## Changing a Page's Category

Change the `system-category` field in the editor and save. A public page stays in the pages folder. A private page can only be in a category stored as `vault`; the editor does not offer the Private box for the others.

## Common Questions

### Q: Can I manually move page files?

__A:__ No. Change the page in the editor (its category, or its Private box) and let the system move the file.

### Q: What happens if I use an invalid category name?

__A:__ The editor only offers the categories the platform knows; pick one of those.

### Q: Why are filenames UUIDs?

__A:__ UUIDs provide:

- Uniqueness (no conflicts)
- Stability (renaming pages doesn't break links)
- Security (harder to guess file locations)
- Works with any language/character set

### Q: How do I find a page file on disk?

__A:__ View the page and check the "More Information" section to see its UUID, then look for `[uuid].md` in the pages folder (or the owner's vault, for a private page).

## Configuration

Categories are configured in `config/app-default-config.json`, and can be overridden per site. `storageLocation` decides where a category's pages are stored: no `storageLocation` means `none`, a `storageLocation` without `privatestore` means `public`, and one with a `privatestore` means `vault`:

```json
{
  "ngdpbase.system-category": {
    "documentation": {
      "label": "documentation",
      "description": "End-User documentation",
      "enabled": true,
      "storageLocation": { "defaultstore": "pages/" }
    },
    "general": {
      "label": "general",
      "description": "General User pages",
      "default": true,
      "enabled": true,
      "storageLocation": {
        "defaultstore": "pages/",
        "privatestore": "pages/vaults/{user}/default/"
      }
    }
  }
}
```

## Troubleshooting

### Page not appearing after save

- Check category name is spelled correctly
- Check category is enabled in configuration
- Restart server with `./server.sh restart`

### Saving is refused for a category

- The category has no `storageLocation`, so its pages are never stored on the platform. Give it one, or pick another category

### Cannot delete page

- Shipped pages (from the release or an add-on) need an administrator

## Best Practices

__Do:__

- Always include complete metadata
- Use appropriate category for content type
- Choose descriptive titles and keywords
- Let the system place the file

__Don't:__

- Manually move page files
- Use invalid category names
- Skip [Frontmatter] metadata
- Rename files directly on filesystem

## File Structure

```text
data/
└── pages/                              # Every public page
    ├── 1a2b3c4d-5e6f-7890-abcd.md      # A general page
    ├── 7682c617-555f-4322-9820.md      # This page (a shipped copy)
    └── vaults/
        └── jane/
            └── default/                # Jane's private general pages
                └── 2b3c4d5e-6f78-90ab-cdef.md

required-pages/                         # In the release: the originals of shipped pages
└── 7682c617-555f-4322-9820.md
```

See [Page Metadata Documentation] for metadata field details, [system-category] for category configuration, and [Frontmatter] for the page metadata format.
