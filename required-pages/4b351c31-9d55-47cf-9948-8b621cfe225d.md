# Overview

[{$applicationname}] keeps rendered pages in memory to improve response times. A cached page is kept up to date automatically: when a page is saved, renamed or deleted, when an account changes, when configuration is saved, or when attachments or the media library change, every page that shows that information is rendered again the next time someone views it. Anything that shows the time, uptime or who is signed in is refreshed at most once a minute. Administrators can still flush the cache at once or evict a single page.

## When to Clear Cache

Normal editing in the application keeps the cache current, so manual clearing is rarely needed. Clear it when:

- A template, plugin or layout change (for example after an upgrade) is not reflecting on existing pages
- A page file was edited directly on disk (outside the editor) — evict that page
- Required pages have been updated on disk and the changes are not visible

## Clearing All Caches

- 1 Go to __Admin → Clear Cache__
- 2 Confirm the action when prompted
- 3 The server clears all in-memory caches and displays a confirmation message

The operation is fast and does not require a server restart. Users may notice slightly slower page loads briefly while pages are rendered again.

## Clearing a Single Page Cache

To evict one page without flushing everything, use the API endpoint:

```
POST /api/admin/cache/clear/page/{identifier}
```

Where `{identifier}` is the page UUID, slug, or title. Requires an active admin session and the session's CSRF token, sent in the `x-csrf-token` header.

Example using curl (replace the UUID, cookie and token):

```bash
curl -X POST https://yoursite/api/admin/cache/clear/page/b06973bc-56c2-4da0-8702-08408de8c207 \
  -H "Cookie: connect.sid=your-session-id" \
  -H "x-csrf-token: your-csrf-token"
```

Response:

```json
{ "success": true, "evicted": "Page Title", "identifier": "b06973bc-..." }
```

`evicted` is the title of the page that was evicted, or `null` when no page matched the identifier. Evicting a page also makes every other cached page render again on its next view, so pages that list or include it pick up the change too.

## What Is Cleared

%%table-striped
|| Scope || Clears ||
| All caches (Admin UI) | Every rendered page held in memory |
| Single page (API) | The stored copy of that one page's text, read again from disk; every cached page renders again on its next view |
/%

The page index, search index, and user sessions are __not__ affected by either operation.
