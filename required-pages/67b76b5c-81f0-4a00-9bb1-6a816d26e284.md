# Reindex Pages

__Reindex Pages__ refreshes the page list the server holds in memory and rebuilds the search structure from the __persisted search document cache__. It is the fast, routine maintenance action.

> __Important:__ Reindex rebuilds search from the *cached* documents, and it does not rewrite the saved page list (`page-index.json`) the server reads at every start. A deleted page still showing in search, or a page that says "page not found" although it is there, is __not__ fixed by Reindex — or only until the next restart. Use __[Rebuild Pages](/view/rebuild-pages)__, which rewrites the saved page list and the search index from what is on disk.

## When to Reindex

Reindexing is rarely needed under normal operation. The system keeps the index updated automatically as pages are created, edited, or deleted. Reindex when:

- Pages appear missing from search results after a bulk file operation
- The server was stopped while pages were being written
- After restoring a backup or importing pages

For pages that were __removed or renamed directly on disk__, deleted pages still showing in search, or pages that stop opening after a restart, use __[Rebuild Pages](/view/rebuild-pages)__ instead — Reindex will not correct those entries.

## How to Reindex

- 1 Go to __Admin → Reindex Pages__
- 2 Confirm the action when prompted
- 3 The server refreshes its in-memory page list and rebuilds the search index
- 4 A confirmation message shows the page count and search document count when complete

On a large instance (10,000+ pages), reindexing may take a minute and will temporarily cause higher memory usage while the search index is built.

## What Is Rebuilt

- __In-memory page list__ — which pages exist and where each file is, re-read from disk; the saved page list (`page-index.json`) is not rewritten — that is __[Rebuild Pages](/view/rebuild-pages)__
- __Search index__ — the full-text search structure, rebuilt from the persisted document cache (not a clean disk re-scan)
- __Links between pages__ — the Referring Pages graph

User sessions, attachments, and media are not affected.
