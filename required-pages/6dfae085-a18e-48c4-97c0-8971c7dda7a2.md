# Updating Add-ons

Some add-ons on [{$applicationname}] are installed from npm, the public package registry. The [Add-ons|/admin/addons] page lists them under __Installed from npm__, and lets an administrator move each one to a newer version.

## What the page shows

For each add-on installed from npm:

- __Installed__: the version the site runs now.
- __Allowed range__: the versions the site's configuration allows, such as `^1` (any 1.x version).
- __Newest in range__: the newest version npm has within that range. The page asks npm each time you open it, or when you press __Check__.
- __Action__: __Update to X__ when a newer version in the range can be installed, or __Up to date__.

If the newest version needs a newer version of [{$applicationname}] itself, the page shows "needs ngdpbase ≥ X" instead. That version can be installed only after the site itself is updated.

## Updating an add-on

- 1 Open the [Add-ons|/admin/addons] page and find the add-on under __Installed from npm__.
- 2 Press __Update to X__ and confirm.
- 3 The site checks the new version before keeping it: that it is exactly what npm published, and that it was built from the add-on's own source repository. A version that fails a check is not installed, and the page says why.
- 4 The page then says "Restart the site to use version X". Until the restart, the site keeps running the version it had.
- 5 Restart the site. The add-on now runs the new version.

You may need to sign in again before the update starts. Updating an add-on needs the permission to change site settings.

## Restarting never updates

A restart never moves an add-on to a newer version on its own. Only the __Update__ button does. A site restarted while npm is down starts on the versions it already has.

## If npm can't be reached

The page says that npm couldn't be reached. Nothing changes: the site stays on the versions it has. Press __Check__ or __Update__ again later.

## If the new version doesn't start

The site keeps the previous version until the new one has started successfully. If the new version fails to start:

- the previous version is put back, and runs again after the next restart;
- administrators get a notification saying which version failed and why;
- until that restart, the add-on is not running.

If the site stops while starting the new version, the next start goes back to the previous version by itself.

## Who did what

Every update is recorded in the [audit log|/admin/audit]: who pressed Update, which add-on, and from which version to which. Going back to a previous version after a failure is recorded too.
