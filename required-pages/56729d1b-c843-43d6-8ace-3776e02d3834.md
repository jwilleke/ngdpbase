# Page Private

The __Private__ setting makes a page readable only by its __owner__ — nobody else, administrators included. It is the strongest per-page access control and overrides every other view or edit rule on the page.

## What It Does

When Private is enabled on a page:

- Only the __owner__ (the page's author, as recorded when it was first saved) can view, edit, or otherwise act on the page
- Nobody else reaches it because of a role. An administrator gets the same refusal as any other user
- The page is kept in the owner's own __private area__, so it stays out of other people's search results and page listings
- All other per-page settings — [Page Audience], [Author Lock], and any `access` overrides — are __bypassed__. The Private rule decides alone.

## How To Set It

- On a page's __Edit__ form, check the __Private__ checkbox
- On the __Create New Page__ form, check the __Private__ checkbox at creation time
- In page frontmatter directly:

```yaml
private: true
```

The dedicated `private` frontmatter field is the canonical signal. Earlier versions of [{$applicationname}] used a `user-keywords: [private]` entry; that mechanism was removed in v3.7.0. All existing pages have been migrated. New pages should use only the top-level `private` field.

## Who Can Set or Remove It

- __The owner__ can toggle Private on or off
- Nobody else can, administrators included: they cannot open the page to change the setting

## Precedence Over Other Settings

Private is the highest-priority per-page rule. When `private: true` is set:

%%table-striped
|| Setting || Effect when Private is on ||
| [Page Audience] | Ignored — does not grant or deny view |
| `access: { view, edit, delete }` | Ignored — does not grant or deny anything |
| [Author Lock] | Ignored — Private already restricts every action to the owner |
| Global access policies | Ignored — Private decides alone |
/%

Removing Private (setting `private: false` or unchecking the box) restores normal evaluation through Audience / access / global policies.

## Who Owns the Page

Ownership is the page's author as recorded when the page was first saved. Editing the `author` field in the frontmatter afterwards does not change who owns the page, so it cannot be used to take a private page from its owner or hand it to somebody else.

## What Private Does NOT Do

- Does __not__ hide the page from someone who can read the server's disk or its backups — the files are not encrypted, so keep secrets off them
- Does __not__ give you a way to share the page with a chosen person — private means private to you; use [Page Audience] on a normal page instead
- Does __not__ leave files behind: a file uploaded onto a private page is private too and belongs to the page's owner. A file that is already public stays public when a private page links to it
