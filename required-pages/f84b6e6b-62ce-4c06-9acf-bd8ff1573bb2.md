# Required Pages Sync

The __Required Pages Sync__ page (`/admin/required-pages`) compares the built-in `required-pages/` source files shipped with ngdpbase against the live pages and allows administrators to synchronize them.

## Overview

Required pages are pages that ngdpbase ships with — documentation pages, plugin reference pages, and system pages. They are stored in the `required-pages/` directory in the application source and are the authoritative source for those pages. The sync tool detects when live content has diverged from the source and provides tools to bring them back in line.

## Status Values

Each required page is shown with one of four statuses:

%%table-striped
|| Status || Color || Meaning ||
| __Current__ | Green | The text of the live page matches the source. No action needed. |
| __Modified__ | Yellow | The text of the source differs from the live page. The live page is out of date. |
| __New__ | Blue | The source page does not yet exist in the live pages. It has never been synced. |
| __UUID Mismatch__ | Red | A different page with the same name already exists on this site: its title or slug is the same as the shipped page's. Choose what to do with it (see below). |
/%

Addon pages are listed the same way, in their own section, and can reach __UUID Mismatch__ for the same reason.

Only the page text is compared. Details such as the created and last-modified dates are set by [{$applicationname}] when a page is saved, so they never make a page show as __Modified__.

Required pages can be edited by administrators only. A page whose access an administrator has changed keeps that access, including through a sync.

A page marked __User Edited__ has been changed in [{$applicationname}] since it was last synced. __Sync__ skips it so those edits are not lost; __Force Sync__ replaces them with the source. Force Sync asks you to confirm first. The edited version stays in the page's history.

Forms an add-on ships are not synced here: the add-on replaces them itself when a newer version of it starts. See [Form Definition Reference].

## Actions

### Sync

Copies the source file from `required-pages/` into the live pages directory (`data/pages/`). Applies to pages with status __New__ or __Modified__.

- __Sync All New__ — copies all new source pages to the live pages
- __Sync All Outdated__ — copies all new and modified source pages
- __Sync Selected__ — copies only the pages you have checked

### Diff

Available for __Modified__ and __UUID Mismatch__ pages. Opens a side-by-side or unified diff view comparing the source file content against the live page content. A full-page diff view is also available.

### UUID Mismatch

A shipped page shows __UUID Mismatch__ when a different page with the same name already exists on this site, so the shipped page can't be added next to it. The name must be the same to clash: the same title, or the same slug, ignoring capitals. A plural is a different name, so a shipped page called "Reviews" does not clash with a page called "review".

The screen explains these buttons above the list. For each mismatched page:

- __Diff__ — shows the shipped page and the page already here side by side. It changes nothing.
- __Adopt UUID__ — keeps the page already here, with its text and history, and makes it this shipped page from now on, so later updates are offered for it. Use it only when the page here really is this page, such as an older copy.
- __Replace__ — moves the page already here to the trash and adds the shipped page in its place.
- __Don't Seed Here__ — keeps the page already here, unchanged, and stops offering the shipped page on this site. You can undo it under __Not Seeded Here__.

__Adopt UUID for All__ and __Replace with Source__ do Adopt UUID, or Replace, for every mismatched page at once.

Add-on pages offer only __Don't Seed Here__ for a mismatch.

## Not Seeded Here

Pages you decline appear in the __Not Seeded Here__ list, with the page they clashed with, who declined it and when. The platform stops offering them, so they no longer appear as missing each time the site starts.

The list shows which set each page is shipped in — the built-in required pages, or the name of the add-on — because the same page can be shipped by more than one. Declining a page from one set says nothing about the other.

__Seed Here__ offers a page again. Syncing a declined page directly does the same: asking for it plainly undoes the earlier decision.

## Summary Badges

The top of the page shows badge counts for each status:

- __UUID Mismatch__ count (shown only when mismatches exist) — always addressed first
- __New__ count
- __Modified__ count
- __Current__ count
- __Total__ source pages

## Source Location

Required page source files live in the `required-pages/` directory of the ngdpbase application. Each file is named `{uuid}.md` where the UUID is the canonical identifier for that page. These files are checked into the application repository and updated with each release.
