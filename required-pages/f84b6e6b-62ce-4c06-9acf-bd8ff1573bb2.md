# Required Pages Sync

The __Required Pages Sync__ page (`/admin/required-pages`) compares the pages that ship with [{$applicationname}] against the copies on this site and lets administrators bring them up to date.

## Overview

Required pages are pages that ngdpbase ships with — documentation pages, plugin reference pages, and system pages. The shipped version is the reference for those pages. The sync screen shows which pages on this site differ from the shipped version, and why, so you can update them safely.

## What each page shows

Each page is shown with one of these labels:

%%table-striped
|| Label || Color || Meaning ||
| __Same as shipped__ | Green | The page on this site matches the shipped version. No action needed. |
| __Update ready__ | Yellow | A newer version came with this release, and nobody has changed the page on this site. __Sync All__ updates it. A page whose header can't be read also shows as __Update ready__, with a note under it, and updating it repairs it. |
| __Edited here, not confirmed__ | Gray | The page was changed on this site, and nothing shows that the shipped version has changed since. __Sync All__ leaves it alone. |
| __Edited here, and a newer version is available__ | Red | The page was changed on this site, and a newer shipped version is also available. __Sync All__ leaves it alone. |
| __New__ | Blue | The shipped page is not on this site yet. |
| __UUID Mismatch__ | Red | A different page with the same name already exists on this site: its title or slug is the same as the shipped page's. Choose what to do with it (see below). |
/%

Addon pages are listed the same way, in their own section, and can reach __UUID Mismatch__ for the same reason.

Under the label, a row also shows which release its copy matches: "Your copy: v5.43.0". The release ngdpbase ships now is said once in the header of each section: "This release: v5.45.0", and for add-ons one name and version each. For a page from an add-on, the release is that add-on's version. When the copy is behind the shipped page, the row says "Your copy: an earlier release", because the release it came from is not known. The release is only a note for you: the page text still decides the label. A __New__ page has no copy yet, so it shows no "Your copy".

When someone edits one of these pages, the editor says so: "This page came with the software. Your changes stay on this site: an update will not replace them." The edited page then shows up here as __Edited here, not confirmed__, where an administrator confirms the change was meant or puts the original back.

Only the page text is compared. Details such as the created and last-modified dates are set by [{$applicationname}] when a page is saved, so they never make a page show as changed.

Required pages can be edited by administrators only. A page whose access an administrator has changed keeps that access, including through a sync.

A page marked __Edited here__ has been changed on this site. __Sync All__ never replaces it, so those edits are not lost. To replace it with the shipped version, choose __Use shipped version__ on its row. You are asked to confirm first, and the edited version stays in the page's history.

Forms an add-on ships are not synced here: the add-on replaces them itself when a newer version of it starts. See [Form Definition Reference].

## Actions

### Sync and update

Each row has one button, and its label says what it does:

- __Sync__ — adds a __New__ page to this site.
- __Update__ — replaces an __Update ready__ page with the shipped version.
- __Use shipped version__ — replaces a page that was edited here with the shipped version, after you confirm.

The buttons above the list work on many pages at once:

- __Sync All New__ — adds every __New__ page.
- __Sync All__ — updates only the pages marked __Update ready__. Pages edited here are never changed by it, and the message after it runs says how many edited pages were left alone. When no page is ready the button is greyed out.
- __Sync Selected__ — syncs only the pages you have checked.

### Diff

Available for pages that differ from the shipped version, and for __UUID Mismatch__ pages. Opens a side-by-side or unified diff view comparing the shipped page against the page on this site. A full-page diff view is also available.

### UUID Mismatch

A shipped page shows __UUID Mismatch__ when a different page with the same name already exists on this site, so the shipped page can't be added next to it. The name must be the same to clash: the same title, or the same slug, ignoring capitals. A plural is a different name, so a shipped page called "Reviews" does not clash with a page called "review".

The screen explains these buttons above the list. For each mismatched page:

- __Diff__ — shows the shipped page and the page already here side by side. It changes nothing.
- __Adopt UUID__ — keeps the page already here, with its text and history, and makes it this shipped page from now on, so later updates are offered for it. Use it only when the page here really is this page, such as an older copy.
- __Replace__ — moves the page already here to the trash and adds the shipped page in its place.
- __Don't Seed Here__ — keeps the page already here, unchanged, and stops offering the shipped page on this site. You can undo it under __Not Seeded Here__.

__Adopt UUID for All__ and __Replace with Source__ do Adopt UUID, or Replace, for every mismatched page at once.

Add-on pages offer only __Don't Seed Here__ for a mismatch.

## Not Seeded Here

Pages you decline appear in the __Not Seeded Here__ list, with the page they clashed with, who declined it and when. The platform stops offering them, so they no longer appear as missing each time the site starts.

The list shows which set each page is shipped in — the built-in required pages, or the name of the add-on — because the same page can be shipped by more than one. Declining a page from one set says nothing about the other.

__Seed Here__ offers a page again. Syncing a declined page directly does the same: asking for it plainly undoes the earlier decision.

## Summary Badges

The top of the page shows badge counts:

- __UUID Mismatch__ count (shown only when mismatches exist) — always addressed first
- __Title Drift__ count (shown only when a page's title here differs from the shipped title)
- __New__ count
- __Update ready__ count — pages __Sync All__ will update
- __Edited here__ count — pages changed on this site, which __Sync All__ never changes
- __Same as shipped__ count
- Total source pages

Each table has its own line in its header, next to its own __Sync All__ button: how many of that table's pages need a decision, and how many its __Sync All__ will update ("3 need a decision; Sync All updates 6"). When no page is ready, it says so instead of showing a zero. A line below the badges says how to act on an edited page: open __Diff__, then choose __Use shipped version__.

After a __Sync All__ the badges update at once, before the page reloads. The __Source Modified__ column shows the date a shipped page last changed, as year-month-day.

## Push to Source

__Push to Source__ copies a page's text from this site back into the shipped pages, so every later release starts from it. It shows only when this site runs from a source checkout of [{$applicationname}]: a copy run from its source code, the way a developer runs it, and not an installed release. On a source checkout a person can commit the change. On an installed site there is no shipped copy to change, so the button is hidden and a request for it is refused. It asks first: "Make this site's text the version every release ships?"

## Where shipped pages come from

Shipped pages come with each release of [{$applicationname}]. Updating [{$applicationname}] brings in the newer versions, and this screen is where you choose to apply them. Nothing replaces a page on this site when [{$applicationname}] starts.
